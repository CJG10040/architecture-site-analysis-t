# 구현·누락·완료 기준 감사

작성일: 2026-08-30
대상 저장소: `CJG10040/architecture-site-analysis-t`
기준 커밋: `fef8befd9f5e7a8a968d5e3c590421c51cea065e`

## 1. 감사 결론

현재 프로젝트는 **대지선정·자료수집·원자료 보존·기초 결정론적 요약·코드 수준의 주변 건축물 데이터 기반**까지 진행되었다.

그러나 당초 목표인 다음 흐름은 아직 끝나지 않았다.

```text
필지 확정
→ 조사 분야 선택
→ 관련 자료 수집
→ 건축물별 통합 master를 실제 프로젝트에 저장
→ 범위별 결정론적 건축물 분석
→ 현장 관찰과 건축물 연결
→ 건축물 분야 AI 분석
→ 사용자 검토·분야 완료
→ 다음 분야
```

특히 C-01~C-05는 코드·합성 샘플 테스트 기반은 만들어졌지만, 현재 Home/Preflight/Store에서 실제 `BuildingStudy`를 채우고 화면에 보여주는 end-to-end 경로는 연결되지 않았다. 따라서 이 항목들은 **기반 구현 완료, 제품 기능 완료 전** 상태로 다시 분류한다.

## 2. 현재 상태를 과장하고 있던 부분

### 2.1 TODO 상태

기존 TODO에서 B-01이 `진행 중`으로 남아 있는 반면 C-01~C-05가 `완료`로 표시되어 상태 기준이 일관되지 않았다.

감사 후 원칙:

```text
B-01: 문서·자료원 감사 완료
C-01~C-05: 기반 코드 완료 / 실제 파이프라인·화면·샘플 검증 전이므로 진행 중
```

### 2.2 카탈로그의 implemented·partial

카탈로그의 `implemented`는 "코드상 호출·기록 경로가 있음"이라는 의미로 유지한다. 실제 서비스에서 API 키·domain·CORS·최신 응답까지 확인했다는 의미로 확장하지 않는다.

`partial`은 다음 중 하나라도 남아 있으면 유지한다.

```text
실제 필드 검증 전
식별자 결합률 미검증
지도·저장 경로 미연결
공간관계 계산 미완료
공식 기준일·갱신일 미확인
```
