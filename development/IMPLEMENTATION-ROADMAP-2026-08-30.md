## 0. 일정 원칙

이 로드맵의 날짜는 고정 배포 약속이 아니라 작업 순서를 명확히 하기 위한 예상 개발 회차다. 실제 API 승인·CORS·현장자료 확보가 지연되면 해당 항목은 숨기지 않고 `blocked`로 기록한다.

```text
코드 기반 완료
→ 실제 샘플 확인
→ 프로젝트 저장 연결
→ 화면 확인
→ 사용자 검토
→ 다음 단계 진입
```

중요한 정책은 **주변 건축물 분야를 실제로 완료하기 전 다른 조사 분야의 자동수집을 대량으로 늘리지 않는 것**이다.

### 검증


### 통과 게이트

- 실제 응답이 원본으로 보존된다.
- 합성 테스트가 아닌 실제 샘플로 매칭 결과를 확인한다.
- 실패·빈 응답·미매칭을 성공으로 표시하지 않는다.
- `BuildingStudy`가 실제 프로젝트에 저장된다.

## 3. 2회차 — 건축물 분야 결정론적 공간분석

예상 시기: C-06 통과 직후
대상: D-01~D-04

### 순서

```text
D-01 거시
→ D-02 중간
→ D-03 대지
→ D-04 미시
```

### 구현 지표

#### 거시 300m 초과~1km

```text
건축물 수·밀도
footprint 면적 분포
층수·높이 분포
건축 시기 분포
용도 구성
건축물 군집
```

개별 상세값을 과도하게 AI에 보내지 않고 집계와 분포로 사용한다.

#### 중간 100m 초과~300m

```text
건물군 cluster
건물 사이 거리
형태상 빈 공간 비율
용도 혼합
높이 전이
건물 방향성
```

형태상 빈 공간은 공공공간·보행 가능 공간·소유권 없는 공간과 구분한다.

#### 대지 30m 초과~100m

```text
대지 각 변별 인접 건물
경계까지 거리
인접 건물 footprint·용도·층수·높이
대지와 건물 관계
```

#### 미시 0~30m

```text
1층 접촉면
출입구·전면부
벽면·창호·차양
공실·활동·재료
현장관찰과 공공데이터의 일치·불일치
```

현장 확인이 없는 항목은 미확인으로 남긴다.

### 통과 게이트

- 모든 수치에 계산 기준과 공간범위가 있다.
- `FACT`, `RELATION`, `UNKNOWN`이 분리된다.
- 0개가 부재인지 API 실패인지 구분된다.
- 인접 건축물별 근거 ID가 유지된다.

## 4. 3회차 — 건축물 전용 화면과 자료 품질 패널

예상 시기: D 분석 함수가 테스트된 직후
대상: D-05 및 C-06 화면 연결

### 화면 순서

```text
건축물 조사 시작
→ 범위 선택
→ 품질 요약
→ 지도
→ 건축물 목록·상세
→ 관계·분포 차트
→ 단면/높이 전이
→ 관찰 연결
```

### 필수 표시

```text
전체 분석 객체 수
지도 표시 객체 수
유효·무효 객체
출처별 매칭률
필드 누락률
충돌·후보 수
기준일·공간범위
계산값·공식값·추정값·미확인값
```

### 통과 게이트

- 사용자가 건축물 한 개를 선택해 원자료·정규화값·결합근거를 볼 수 있다.
- 지도 300개 제한과 전체 분석 개수가 혼동되지 않는다.
- 품질이 낮은 필드는 시각적으로 확인된다.
- 브라우저 새로고침 후 화면이 복원된다.

## 5. 4회차 — 현장관찰과 건축물 연결

예상 시기: 건축물 화면 완료 직후
대상: F-01의 전단계 + 미시 입력 보강

### 입력 보강

```text
사진
촬영시각
촬영 위치
촬영 방향
대상 건축물 ID
관찰 유형

```

관찰 유형:

```text

```

### 통과 게이트

- 관찰 하나가 특정 건축물과 연결된다.
- 사진·위치·시각이 보존된다.
- 관찰과 공식자료의 불일치를 별도로 저장한다.
- 현장에 가지 않은 정보가 관찰로 표시되지 않는다.

## 6. 5회차 — 건축물 분야 전용 AI 분석

예상 시기: D-05와 현장 연결 통과 직후
대상: E-01~E-05

### 입력

건축물 분야 자료만 전달한다.

```text
범위별 master 집계
건축물별 근거
공간관계
생애 이벤트
현장관찰
데이터 품질·공백·충돌
```

자료별 5,000자·전체 약 90,000자 제한을 유지한다.

### 출력 강제

```text
FACT 5개 이상
RELATION 5개 이상
INTERPRETATION
ISSUE 3개 이상
근거 있는 KEYWORD
FIELD QUESTION
DESIGN QUESTION 3개 이상
서로 다른 HYPOTHESIS 3개 이상
각 가설의 장점·위험·검증항목
UNKNOWN
```

각 사실·관계·이슈·가설에는 건축물 ID·자료 ID·공간관계 근거 ID가 있어야 한다.

### 통과 게이트

- 자유 텍스트만 저장하지 않고 `BuildingAnalysis`에 구조화 저장한다.
- 근거 없는 수치·교통량·소음·법규값을 거부한다.
- 사용자가 이슈를 동의·반박·수정할 수 있다.
- AI 결과와 결정론적 계산 결과를 구분한다.

## 7. 6회차 — 실제 대지·QGIS·건축학도생 검증

예상 시기: 건축물 AI 결과가 저장된 직후
대상: F-01~F-04

### 검증 순서

```text
충장로1가·금남로1가 대상지 실제 수집
→ QGIS 표본 비교
→ 웹 master 비교
→ 현장사진·관찰 비교
→ AI 주장 근거 점검
→ 사용자 검토
```

### 비교 항목

```text
건축물 수
footprint 위치
footprint 면적
식별자 결합
층수·높이·용도
건물 간 거리
대지 각 변 인접관계
```

### 완료 게이트

- 실제 대지에서 수집·저장·재개방이 된다.
- QGIS와 불일치 항목이 기록된다.
- 자료 오류·현장 불일치·공백이 분석에 반영된다.
- 사용자가 건축물 분야 완료를 승인한다.

이 게이트를 통과하기 전에는 도로·환경·생활권 분야를 전체 종합에 넣지 않는다.
